# Безопасность / Security

## Модель угроз (кратко)

- **Root-права.** TUN-режиму нужен root: он меняет default route и создаёт
  устройство `urnetwork`. Установщик `scripts/install-nopasswd.sh` копирует
  launcher и бинарники в `/usr/local/libexec/urnetwork/` (владелец root) и
  выдаёт `NOPASSWD` только на эту копию. NOPASSWD на файлы внутри git-чекаута
  (как было раньше) эквивалентно passwordless root и не поддерживается.
- **Пароль sudo.** У GUI нет терминала, поэтому при необходимости GUI передаёт
  `SUDO_ASKPASS=scripts/urnetwork-askpass.sh`; помощник открывает отдельное окно
  терминала, и набранный пароль уходит прямо в `sudo`, не через `argv` и не
  через файл на диске.
- **Пароль URnetwork.** По умолчанию хранится в системном хранилище секретов
  (GNOME Keyring / Secret Service) через `scripts/urnetwork-credentials.py`.
  В `~/.config/urnetwork/auth` остаются только `USER_AUTH`/`NETWORK_NAME`;
  fallback — файл с правами `0600`. Пароль никогда не передаётся в `argv`:
  только через окружение (GUI/CLI) или stdin (helper).
- **SOCKS5.** Слушает `127.0.0.1:9999`; аутентификации нет, поэтому наружу
  открывать не следует — клиент предупредит, если bind не loopback.
- **TLS.** Минимальная версия — 1.3 для API и control-соединений.

## Что считается уязвимостью

- обход этих границ (пароль в `ps`/логах, NOPASSWD на user-writable файлы,
  root без запроса пароля, утечка трафика мимо туннеля при включённом VPN);
- удалённо триггерящиеся паники/падения (пример: пустой IP-пакет от пира);
- чтение/запись файлов вне конфигурационного каталога с правами root.

## Как сообщить

Откройте приватный security advisory в GitHub
(`Security` → `Report a vulnerability`) или создайте issue без публикации
эксплойта. Пожалуйста, приложите версию, вывод `make test` и шаги
воспроизведения.
