# Безопасность / Security

## Модель угроз (кратко)

- **Root-права.** TUN-режиму нужен root: он меняет default route и создаёт
  устройство `urnetwork`. Установщик `scripts/install-nopasswd.sh` копирует
  launcher и бинарники в `/usr/local/libexec/urnetwork/` (владелец root) и
  выдаёт `NOPASSWD` только на эту копию. NOPASSWD на файлы внутри git-чекаута
  (как было раньше) эквивалентно passwordless root и не поддерживается.
- **Что попадает в root-процесс.** После ревью sudoers-правило сохраняет только
  `URNETWORK_VERBOSE` (`Defaults!$DEST env_keep += "URNETWORK_VERBOSE"`).
  Учётные данные передаются root-копии launcher'а файлом
  `~/.config/urnetwork/.creds.<pid>` с правами `0600` и владельцем
  пользователя; launcher проверяет владельца, читает файл и сразу удаляет.
  `URNETWORK_CONFIG_DIR` и `URNETWORK_STATE_FILE` больше не проходят в root:
  каталог конфигурации выводится из `SUDO_USER`, а путь к state-файлу root-движок
  принимает только внутри доверенного каталога пользователя
  (`resolveStateFilePath` в `cmd/urnetwork-vpn/main.go`). Запуск `register` под
  root запрещён.
- **Пароль sudo.** У GUI нет терминала, поэтому при необходимости GUI передаёт
  `SUDO_ASKPASS=scripts/urnetwork-askpass.sh`; помощник открывает отдельное окно
  терминала, и набранный пароль уходит прямо в `sudo` — не через `argv` и не
  через файл на диске.
- **Пароль URnetwork.** По умолчанию хранится в системном хранилище секретов
  (GNOME Keyring / Secret Service) через `scripts/urnetwork-credentials.py`.
  В `~/.config/urnetwork/auth` остаются только `USER_AUTH`/`NETWORK_NAME`;
  fallback — файл с правами `0600`. Для GUI и обоих движков пароль передаётся
  только через окружение или stdin helper'а. Исключение — шаг `register`:
  он передаёт пароль сторонней библиотеке upstream в `argv` (так устроен
  провайдер), поэтому в момент регистрации пароль виден в `ps`; после
  регистрации пароль в `argv` не попадает.
- **Процессы.** `off` не убивает процессы «по имени»: launcher сверяет
  `/proc/<pid>/exe` с ожидаемым бинарником и только потом шлёт сигнал; широкого
  `pkill -f` больше нет. Журнал маршрута (`default-route.before`) проверяется
  маской перед применением — подменённый файл не станет `ip route` от root.
- **SOCKS5.** Слушает `127.0.0.1:9999`; аутентификации нет, поэтому наружу
  открывать не следует — клиент предупредит, если bind не loopback.
- **TLS.** Минимальная версия — 1.3 для API и control-соединений.

## Известные ограничения

- `register` — единственное место, где пароль оказывается в `argv` (см. выше).
- GUI читает пароль из Secret Service на главном потоке GTK: если сервис
  секретов завис, старт GUI может задержаться до таймаута (20 с).
- GUI не учитывает `URNETWORK_CONFIG_DIR` (использует `~/.config/urnetwork`) —
  расхождение с CLI-скриптом.
- В VPN-режиме root-копия использует только каталог из `SUDO_USER`; нестандартный
  `URNETWORK_CONFIG_DIR` в root-режиме не подхватывается (осознанно: каталог
  конфигурации не должен быть входом для root).

## Что считается уязвимостью

- обход этих границ (пароль в `ps`/логах, NOPASSWD на user-writable файлы,
  root без запроса пароля, утечка трафика мимо туннеля при включённом VPN);
- удалённо триггерящиеся паники/падения (пример: пустой IP-пакет от пира);
- чтение/запись/удаление файлов вне конфигурационного каталога с правами root,
  инъекция маршрутов через подменённый state/journal.

## Как сообщить

Откройте приватный security advisory в GitHub
(`Security` → `Report a vulnerability`) или создайте issue без публикации
эксплойта. Пожалуйста, приложите версию, вывод `make test` и шаги
воспроизведения.
