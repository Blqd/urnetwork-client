# Как привлечь аудиторию к urnetwork-client

Практический план на 30 дней: что уже сделано в репозитории, куда идти с
анонсом, что писать, чего нельзя писать по российскому праву и по каким
метрикам мерить результат.

Готовые тексты постов — в [`promotion-posts.md`](promotion-posts.md).

---

## 1. Позиционирование: одну фразу надо выбрать сейчас

Сейчас репозиторий конкурирует «вообще за VPN-клиенты» — это проигрышная
рамка: там сотни проектов и десятки тысяч звёзд. Реальная ниша гораздо уже и
почти пуста:

> **URnetwork-клиент для Linux-десктопа с родным GTK3-интерфейсом и
> установкой одним `.deb`.**

Проверка по GitHub (2026-11-04): `devrandom0/urnetwork-client` — 9★,
`virtual-designer/urnetwork-client-gnu` — 2★, остальные — дашборды и докер-майнеры.
То есть в нише «Linux GUI-клиент URnetwork» максимум девять звёзд: шанс стать
выбором по умолчанию есть, но он живёт ровно до того момента, когда кто-то
сделает то же самое с лучшим README.

Ось дифференциации — не «ещё один VPN», а три проверяемых факта:

| Что | Почему это редкость |
|---|---|
| GTK3 GUI (Python + PyGObject), а не Electron и не CLI | на Linux-десктопе это ~50 МБ разницы и родные темы |
| Один `.deb`: GUI, CLI, man-страницы, desktop entry | не Snap, не Flatpak, не AppImage — `dpkg -i` и всё |
| Пароль в GNOME Keyring, root только для TUN | видно из `SECURITY.md`, это аргумент доверия |

Чего **не** делать в позиционировании: не сравнивать себя с официальным
клиентом по числу функций и не обещать «скорость/анонимность» — это поле
больших игроков, а проверяемого преимущества там нет.

## 2. Аудит страницы репозитория (воронка конверсии)

Звезда ставится обычно за 5–15 секунд просмотра страницы. Что уже исправлено:

- [x] скриншот GUI в первом экране `README.md` и `README.en.md`
      (`docs/assets/screenshot.png`, демо-аккаунт, без реальных данных);
- [x] питч на три пункта + установка из релиза до сборки из исходников;
- [x] topics: было 7, стало 14 (`linux`, `linux-desktop`, `vpn-client`,
      `decentralized`, `urnetwork`, `deb-package`, `open-source` и др.);
- [x] description с «Ubuntu/Linux» и «native GTK3 GUI»;
- [x] Discussions включены, issue-формы и PR-шаблон, `CODE_OF_CONDUCT.md`
      (community profile → 100 %);
- [x] социальное превью 1280×640 — `docs/assets/social-preview.png`.

Что осталось сделать руками (5 минут в веб-интерфейсе):

1. **Social preview**: Settings → Social preview → загрузить
   `docs/assets/social-preview.png`. Без этого ссылка в HN/Reddit/Telegram
   разворачивается в пустую карточку.
2. **About → Website**: поставить ссылку на страницу релизов
   (`https://github.com/Blqd/urnetwork-client/releases/latest`) — так посетитель
   попадает сразу к `.deb`, а не в дерево исходников.
3. **Releases**: перевести тело `v0.1.1` на английский (или продублировать) —
   англоязычная аудитория читает release notes первой.

Проверка после пуша: `gh api repos/Blqd/urnetwork-client/community/profile`
должен показать `health_percentage: 100`.

## 3. Волна 1 — англоязычные каналы (главный охват)

Порядок важен: сначала «своя» площадка, потом агрегаторы. На каждом канале
правила про self-promotion — читать перед постом, иначе бан и минус репутация.

**День 1–2. Show HN.** Заголовок без маркетинга, формат «Show HN: …».
Хорошо работает техническая деталь в заголовке. Пост — в `promotion-posts.md`.
HN даёт 200–2000 визитов за сутки, но и жёсткую критику: отвечать на все
комментарии в первые 3 часа.

**День 2. Reddit, по одному сабреддиту в день, с разными углами:**
`r/Ubuntu` (установка из `.deb`, Ubuntu 22.04/24.04), `r/linux` (только
текстовый пост с техническими деталями, ссылка в конце — иначе удалят),
`r/selfhosted` (P2P-сеть, приватность), `r/privacy` (keyring, минимум
привилегий). Не дублировать один и тот же текст: модераторы видят историю.

**День 3. Lobsters** (`lobste.rs`, тег `linux`) — маленький, но очень
релевантный трафик и вечная ссылка.

**День 4. awesome-списки.** PR в `awesome-selfhosted` (раздел VPN) и
`awesome-linux-software`. Правило: одна строка, формат как у соседей, без
«new!». PR — это ещё и обратная ссылка навсегда.

**День 5–7. Product Hunt** — только если есть чем зацепить (скриншот, GIF);
для десктопного OSS-клиента отдача скромная, но бесплатная.

Реальный ориентир: 50–150★ за первую неделю при удачном HN-посте; без HN —
10–30★.

## 4. Волна 2 — русскоязычные каналы

**Хабр.** Два легальных входа: однократный хаб **«Я пиарюсь»** и техническая
статья (через корпоративный блог — платно). Правила Хабра: п.1 — несанкционированная
реклама и самопиар запрещены, п.4 — запрещён текст, сгенерированный нейросетью,
политика запрещена полностью. Значит формат один: **инженерная статья**, где
проект — иллюстрация, а не предмет рекламы. Три темы, которые там заходят:

1. «Разделяем привилегии в сетевом клиенте: SOCKS5 без root, TUN с root»
   (polkit/pkexec, минимальные права, sudoers-правило на root-owned копию).
2. «`.deb` без PPA: debhelper, GitHub Actions и релизы по тегу» — дефицитный
   практический материал.
3. «Тесты сетевого клиента в netns с `tc netem`: потери, reorder,
   suspend/resume, IPv6».

**OpenNET** — новость о релизе через форму `opennet.ru/add.shtml`; модерация
редактором, поэтому сухой технический текст, без эпитетов.

**linux.org.ru** — предложить новость о релизе; постмодерация, офтоп и реклама
удаляются. Аудитория — ядро Linux-админов, конверсия в звёзды выше средней.

**Telegram** — не «канал», а точечный запрос тестеров в чатах (`@linux_gram`,
`@linux_wit`, `@linuxplz0x41`): «нужны тестеры Ubuntu 24.04, вот что проверить».
Это даёт баг-репорты и первые issues, а не охват.

**vc.ru — не использовать.** Правила прямо запрещают рекламу VPN и обхода
блокировок; пост с упоминанием клиента рискует блокировкой аккаунта.

## 5. Юридические ограничения (РФ) — коротко и по делу

Ключевое различие: **сам репозиторий — не реклама**. Код, MPL-2.0 и
техническое README под запрет рекламы VPN не подпадают. Риск создают
**формулировки в постах** и платные размещения.

- С 01.03.2024 РКН ограничивает страницы со способами обхода блокировок —
  независимо от даты публикации.
- С 01.09.2025 действует **ч.18 ст.14.3 КоАП** (ФЗ № 281-ФЗ от 31.07.2025):
  реклама программно-аппаратных средств доступа к ограниченным ресурсам —
  граждане 50–80 тыс. ₽, должностные лица 80–150 тыс. ₽, юрлица 200–500 тыс. ₽.
- **Ст.13.52 КоАП** — для владельцев VPN/ПАС (неисполнение порядка
  взаимодействия с РКН); повторно — до 1 млн ₽ для юрлиц. Проект остаётся
  в безопасной зоне, пока не начинает продавать доступ/подписку.
- Использование VPN гражданами не наказывается — наказуемо распространение
  рекламы и инструкций под обход.

**Безопасные формулировки:** «open-source клиент децентрализованной P2P-сети»,
«приватное соединение в публичных Wi-Fi», «инженерный разбор», «тестирование
сети», «self-hosted».
**Опасные:** «обход блокировок», «доступ к заблокированным сайтам», «VPN для…»,
«работает в РФ несмотря на блокировки», пошаговые инструкции под эти цели,
призывы, цены.

Практика: ноль платной рекламы, в README — строка-дисклеймер «инструмент для
приватности и тестирования сетей», в постах — архитектура, код и тесты.
Живой пример риска: статья про VLESS/Reality на Хабре сейчас отдаёт 403.

## 6. Дистрибуция — самый недооценённый рычаг

Звезда — следствие установки, а не наоборот. Пока клиент ставится только
через `.deb` из Releases, его не попробует тот, кто не читает README до конца.
Порядок по соотношению «усилие / охват»:

1. **PPA (Launchpad)** — `sudo add-apt-repository ppa:… && sudo apt install urnetwork-client`.
   Полдня работы, покрывает всю Ubuntu-аудиторию и даёт `apt upgrade`.
2. **AUR** (`urnetwork-client-bin`) — Arch-аудитория любит новинки и ставит звёзды.
3. **Flathub** — самая заметная витрина для десктопных Linux-приложений;
   требует манифеста и ревью, но даёт постоянный поток.
4. **Snap Store** — дешевле Flathub, аудитория Ubuntu.
5. **Homebrew tap** — не для Linux-клиента, пропустить.

Пакет в дистрибутиве = страница, которая работает на вас годами.

## 7. Устойчивость: чтобы звёзды не ушли

- **CHANGELOG.md** + английские release notes: проект, у которого «последний
  коммит 5 месяцев назад», не звездят.
- **Roadmap в README** (3–5 пунктов) и **3–5 `good first issue`** с точным
  описанием файла и ожидаемого результата. Это главный источник первых PR.
- **Ответ в течение 24 часов** на issue/PR — в первые недели это решает больше,
  чем любой пост.
- **Участие в upstream** (`urnetwork/extension`, `urfoundation/docker-miner`):
  один комментарий с ссылкой на ваш клиент в обсуждении «а есть ли GUI для
  Linux?» приводит целевой трафик.
- **Не покупать звёзды и не устраивать «взаимные» подписки** — GitHub это
  вычищает, а репутационный ущерб необратим.

## 9. Метрики, которые стоит смотреть

- `gh api repos/Blqd/urnetwork-client/traffic/views` — просмотры и уникальные
  посетители (14 дней истории);
- `traffic/clones` и `traffic/popular/referrers` — откуда пришли;
- скачивания ассетов релиза (`gh release view v0.1.1 --json assets`);
- звёзды/неделя и конверсия «просмотр страницы → звезда»;
- issues/PR от незнакомых людей — главный признак, что аудитория настоящая.

Цели: 30 дней — 100★ и 200 скачиваний `.deb`; 90 дней — 300–500★, PPA и
Flathub, 5+ внешних контрибьюторов.

## 10. Чего не делать

- Писать «обход блокировок», «VPN для доступа к заблокированным сайтам».
- Платная реклама VPN-клиента в РФ (ч.18 ст.14.3 КоАП).
- Постить один и тот же текст во все каналы в один день.
- Покупать звёзды, накручивать фолловеров, рассылать DM.
- Обещать «анонимность» и «скорость» — это непроверяемо и привлекает
  не ту аудиторию.
- Оставлять README без скриншота и без команды установки (уже исправлено).
